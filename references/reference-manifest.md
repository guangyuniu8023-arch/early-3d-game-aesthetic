# 内置参考素材清单与路由

## 使用原则

内置素材用于提供可观察的视觉证据，不是必须全部加载的 moodboard。执行图像、视频或分镜任务时，先根据任务选择素材，再在提示词中说明每张素材的职责与具体参考点。下表路径均相对于 Skill 根目录。

- 用户上传素材优先于内置素材；先说明用户素材负责身份、内容、构图或其他锁定项。
- 单次任务默认选 2–3 张内置素材，最多 3 张。只做单一维度迁移时可只选 1 张。
- 涉及角色时先在 R、J、M 三行中选所属行，再只选一个编号锚点；不得混合多个编号。将该编号的预存档案展开进提示词，编号本身只用于定位。
- 每次只选一个主预设。用户明确要求混合时最多选两个预设，并注明各自负责的不同维度。
- 不把素材整张复制到结果中；只抽取本任务所需的维度。
- 不用未选素材补充角色、地点、UI、敌人、道具或剧情。
- 引用每张参考图时必须同时附带本任务要抽取的 2–4 个具体视觉点；不得只传文件或只写“参考风格”。

## 选择算法

1. 判断产物是场景图、角色设计、UI、视频/分镜、故事/剧本还是完整游戏概念。
2. 判断是否有人物、是否需要运动/特效、是否需要 UI，并选择一个主预设或 `core_only`。
3. 按下表选择最少够用的素材组合。
4. 涉及角色时，从下方固定档案选择唯一编号，将比例、肢体、轮廓和面部表达写进 `reference_plan`；“成年”只定义年龄、职业和叙事身份，不改变锚点比例。
5. 输出 `reference_plan`，逐张写明 `作用`、`具体参考点` 和 `不参考内容`，再生产提示词。

| 任务 | 默认内置素材组合 |
|---|---|
| 有人物的场景图 | 角色系统 + 实时渲染系统 + 主预设 |
| 纯场景图 | 实时渲染系统 + 主预设 |
| 角色设定或立绘 | 角色系统 + 实时渲染系统；题材关系必要时再加主预设 |
| 已有角色的图生图 | 用户图 + 角色系统或实时渲染系统 + 主预设；内置素材最多 2 张 |
| 只做古早低规格 3D 技术化 | 实时渲染系统 |
| 有人物的视频或分镜 | 角色系统 + 动作特效系统 + 主预设 |
| 纯环境或载具运动 | 实时渲染系统 + 动作特效系统 + 主预设 |
| UI 专项 | UI 信息层 + 主预设（需要题材关系时） |
| 故事、剧本或纯文字方案 | 默认不加载图片；只有需要视觉演出说明时才选择主预设 |

如果 UI 被判定为应加入场景图，在上述组合已满 3 张时，不额外加载 UI 信息层；将主预设中的 UI 关系与 `style-guide.md` 的 UI 规则写入提示词。只有 UI 是主要交付对象或结构复杂时，才用 UI 信息层替换较次要的素材。

## 核心素材

| asset_id | path | primary_role | use_when | does_not_prove | combine_with |
|---|---|---|---|---|---|
| `core.character` | `assets/core/core--character-system.jpg` | 角色身形比例、轮廓、类型、身份气质、造型复杂度与时代统一感 | 任务包含人物、怪物或角色设计 | 不证明贴图、材质、光照、动作、场景、UI 或具体身份 | `core.render`；需要时加一个主预设 |

## `reference_plan` 输出格式

```yaml
reference_plan:
  - asset: {asset_id 或用户参考图}
    role: {本任务中的唯一主要职责}
    exact_cues: [{本次实际抽取的 2–4 个可观察点}]
    do_not_copy: [{该素材中不得继承的身份、服装、地点、构图、UI 或偶发细节}]
```

`exact_cues` 必须具体，例如“轻微平滑显示下仍可读的块状肩部轮廓”“低分辨率数字贴图中的大色块与有限明暗”，不要只写“参考风格”或“参考氛围”。
