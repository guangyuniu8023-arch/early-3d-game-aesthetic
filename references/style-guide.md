## 1. 风格定位与证据边界

本风格提炼早期低规格实时 3D 游戏的多样表达，不依赖任何特定平台、品牌或单一作品，也不把所有题材压成同一种滤镜。规则分为：

- **核心不变量**：跨多数分支稳定成立的时代信号
- **条件变量**：只在特定媒介、题材或镜头中启用
- **内容变量**：人物、地点、剧情和道具，不属于核心媒介风格本身
- **创作模块**：剧情、声音和交互建议，只在用户要求相应产物时启用

内置参考板用于观察画面、构图、UI、角色比例和静态动作姿态。静态图不能单独证明完整运镜、剪辑、音乐或动作过程；这些维度是基于对应游戏类型的创作规则，不应覆盖用户明确要求。

## 2. 第一层：古早低规格 3D 核心媒介规则

### 2.1 核心不变量

#### 形体、拓扑与表面着色

- 将“低模本体 + 平滑表面”作为不可拆分的核心：肩、肘、膝、靴子、头部和道具外轮廓显示有限分段，大面积躯干与四肢表面保持连续平滑着色。
- 拓扑主要在轮廓、关节和少量转折处可见；不得把三角形或四边形网格铺满表面作为装饰。
- 五官、衣褶和微小结构优先由贴图暗示，不用现代高模雕刻和细密几何。
- 禁止装饰性三角切面、随机多边形马赛克、wireframe、晶体切割、折纸感和 faceted low-poly 插画风。

#### 贴图与材质

- 使用低分辨率、硬边、颗粒明显的数字贴图外观；光影、污迹和部分高光直接烘焙进贴图。
- 上游提供详细真实材质时先压缩：保留材质身份，但每种材质只写一个综合色块、有限明暗和最多一个辨识特征；多种材质合并为 3–4 个视觉组。
- 不描述织法、毛孔、连续磨损网络、粗糙度、金属度、折射或微表面；金属、布料、皮肤和石材靠色块与单一亮边/暗部区分。
- 压缩示例：做旧棉布写成“暗色哑光色块 + 少量烘焙褶皱”；皮革写成“深色硬边色块 + 一条固定高光”；黄铜写成“黄褐色块 + 一处亮边”，不要继续展开真实材质参数。
- 斜面和大平面允许轻微、视角相关的仿射贴图游动，但表面身份和轮廓保持稳定。

#### 角色比例与面部

- 涉及角色时只使用 [reference-manifest.md](reference-manifest.md) 中一个编号锚点，并把其比例与形体档案展开为文字。“成年”只定义年龄、职业和叙事身份，不意味着现代真人比例。
- 将面部描述分为身份层与表现层：身份层可写深眼窝感、眉形、唇形和情绪；表现层必须把这些特征压缩为低分辨率脸部贴图、少量大色块和极少几何隆起。
- 禁止独立湿润眼球、建模眼睑、鼻孔、唇峰、牙齿、皮肤次表面、毛孔、妆容级细节、细发丝、现代发片和现代 PBR 角色展示渲染。

#### 光影与色阶

- 使用有限阶梯式明暗和简单顶点光照感；大平面保持连续，不用交替明暗的三角形色块表现拓扑。
- 动态光照保持简单，阴影优先使用贴花式 blob shadow、贴图烘焙或少量硬边投影。
- 渐变区域可出现有序抖色、色带或有限色阶，但不要让整个画面被均匀噪点覆盖。
- 色彩方向由题材和场景决定，不创建固定 HEX 色板。

#### 动作与反馈

- 每个动作按“准备并保持—快速执行—结果姿势并短暂停顿—少量过渡后复位或衔接”组织。
- 关键姿势在若干画面中保持不变，再明显切换到下一姿势；不要连续柔顺地加速、减速或使用动作捕捉式补间。
- 减少脚踝、髋部、肩部和手腕的细小自动校正，允许轻微脚滑、硬关节和短促姿态切换；文件输出帧率不等于角色姿势更新频率。

#### 特效与 UI 材质

- 粒子优先使用始终面向相机的 billboard sprite；火花、血滴、烟雾和光点具有有限帧循环。
- 光柱、光环和刀轨由硬边半透明贴片叠加，减少现代体积流体和连续光散射。
- UI 使用清晰硬边窗口、像素或低分辨率字体、有限透明层级；是否出现 UI 由任务决定。

### 2.2 显示层与条件增强项

所有文生视频和图生视频默认使用 `retro_gameplay_display`：画面先表现为低分辨率游戏缓冲画面，再放大到用户指定的最终尺寸。像素簇尺寸跨镜头稳定，使用硬边放大、有限色阶、有序抖色、轻微扫描线、克制的横向色彩溢出和少量高亮辉光；不得把现代高清脸部或材质细节重新补回。只有用户明确要求“干净模型展示”或“无显示屏处理”时改用 `clean_render`。

最终分辨率、画幅和帧率仍继承用户要求；不得通过降低交付文件尺寸实现显示层。静态角色设定、纯素材展示和宣传插画默认不加 CRT，除非用户要求。

其他条件项：

- 顶点/贴图不稳定只允许轻微、视角相关的轮廓跳动和斜面贴图游动；角色比例、拓扑、面部、服装与道具身份必须稳定，禁止新增几何碎片、融化、透明重组或随机换形。
- 距离雾用于遮蔽远景、营造关卡深度或性能边界；室内近景、格斗舞台和清晰 UI 不强制。
- 4:3 是典型实机构图倾向，不覆盖用户明确的最终画幅。
- 压缩色带或块状伪影只在用户明确要求录像或预渲染视频质感时加强。

## 3. 风格强度与保留策略

### `faithful_transfer`

- 必须保持：身份、人数、关系、构图、姿势、场景布局、文字和关键道具，除非用户明确允许改变。
- 默认改变：几何抽象、贴图、材质、有限光影和必要的显示质感。
- 默认禁止：新增敌人、UI、武器、血迹、剧情母题和相机重构。

### `style_enhanced`

- 必须保持：身份、人数、核心关系和剧情事实。
- 可以改变：构图细节、镜头高度、动作姿态、灯光、环境密度、题材 UI 或特效。
- 仍需显式说明每个改变维度，不把整套 preset 自动全部启用。

### `full_gameification`

- 从完整预设中选择当前任务需要的模块，不表示全部开启。只使用简短的 `enabled_modules` 列表，未列出的模块保持关闭。
- 角色图默认只开 `character_shape` 与 `rendering`；场景图默认开 `scene` 与 `rendering`；视频默认开 `camera`、`motion`、`rendering` 与 `display`；UI、剧情、声音和特效按任务决定。
- 核心形体、单一角色锚点、面部简化和表面着色规则优先级高于该模式，不能被游戏化覆盖。

### 场景图 UI 判定

每个场景图都主动判断 UI，但“主动判断”不等于“默认加入”。按以下顺序决定：

1. 用户明确要求有/无 UI 时直接服从。
2. 画面承担操作状态、战斗状态、对话、警戒、导航或交互反馈时，可设为 `include`。
3. 画面是纯环境、角色概念、宣传构图或无界面剧情镜头时，通常设为 `omit`。
4. 无法判断时默认 `omit`，因为无关 UI 会改变构图语义并把概念图误导成实机截图。
5. 设为 `include` 时只加入当前状态必要的组件，并说明组件职能、位置和信息层级；不要为增强“游戏感”堆叠菜单、生命条、雷达和对话框。

输出 `ui_decision: include | omit` 与一句理由。复杂 UI 或 UI 专项任务才调用 `core.interface`；简单状态提示可直接依据主预设与本节规则，不因此突破三张内置素材上限。

### 基础故事与剧本创建

故事模块既支持从零创建，也支持基于原稿改写：

- **从零创建**：从用户给出的主题、角色、地点或一句设定建立前提、主角目标、阻碍、升级节点、高潮选择和结局状态；缺失细节采用最少必要假设，不强行套入预设母题。
- **改写**：先列出必须保留的剧情事实，再调整场景顺序、互动节点、对白长度和演出方式；不擅自改变人物关系、结局或世界观硬约束。
- **游戏化表达**：将叙事拆成可执行场景，每场至少写清目标、冲突、玩家可见信息、状态变化与离场条件。探索、战斗、对话、谜题或系统反馈按剧情需要选择，不要求每场齐全。
- **古早游戏适配**：对白以短句和分屏节奏组织；重要转折交给可读动作、有限镜头和声音钉，不依赖长篇解释或现代连续电影化表演。
- **规模控制**：篇幅、章节数、镜头数和结局数量只继承用户要求；未指定时交付一个简洁、完整、可继续扩写的基础版本。

## 4. 第二层：七个题材预设

每个预设由核心关系、默认视觉、条件模块和漂移防护构成。

### 4.1 `survival_horror`

**核心关系**：受限空间与遮挡 → 不安固定机位 → 转身和瞄准受限 → 声音与画外威胁制造压力。

- 默认视觉：使用所选 R 行编号锚点的低保真人类、压暗废墟或室内、预渲染背景、少量循环灯光或环境动画；“写实”不得改变锚点头身比或增加现代面部精度。
- 相机：每个房间或区域绑定一个固定机位，角色移动时相机不跟随、不环绕、不自动找角度；只有跨过门口或区域边界时硬切到下一固定机位。必要移动仅限短距离单轴脚本轨道；禁止 orbit、dolly、drone、handheld 和连续构图校正。
- 动作：坦克式转身、抱枪跑姿、僵硬前扑、脚本化开门或受击。
- 特效/UI：克制血污贴花、闪光、低帧烟雾；只有战斗或完整游戏化时加入状态 UI。
- 条件剧情：孤立场所、事故、文件叙事、追击者和紧急抉择，仅在剧本或完整游戏化中启用。
- 禁止漂移：不要默认把任何人物图改成丧尸题材；不要对所有镜头同时加血、雾和倾斜构图。

### 4.2 `jrpg_epic`

**核心关系**：预渲染式复杂场景或全 3D 舞台 → 角色与空间层次清楚 → 菜单指令、短促攻击和华丽特效组织节奏。

- 默认视觉：卡通或等身低模角色、细节丰富的背景、清楚的队列与空间层次。
- 相机：探索使用固定或缓慢脚本化机位并保持场景纵深；战斗锁定三分之四侧向舞台。技能演出只允许一次短促切近或单轴推进，随后返回舞台机位；禁止持续环绕和全程电影化追拍。
- 动作：夸张走跑姿态、指令确认后的短促攻击、清楚回位和施法准备。
- UI/特效：行动槽、生命/能量值、命令窗、伤害数字、召唤贴片和光柱仅在对应任务中启用。
- 条件剧情：组队旅行、身份秘密、牺牲、世界性危机和情感副线，仅在剧本或完整游戏化中启用。
- 禁止漂移：不要在同一画面混用冲突的角色比例，不要默认添加蓝色菜单，也不强制设置探索、战斗与过场三套模型。

### 4.3 `stealth_action`

**核心关系**：俯视空间信息 → 敌人视野与警戒反馈 → 蹲伏、贴墙和探头动作 → 剧情时切换电影镜头。

- 默认视觉：冷色工业空间、锐利有限阴影、战术低模角色和清晰遮挡结构。
- 相机：使用受限俯视或斜俯视战术机位，可在固定边界内缓慢跟随，但保持地图方向和警戒空间可读；不穿墙、不绕到角色正面、不自动寻找戏剧角度。警戒事件可短促硬切，随后返回战术轴线。
- 动作：蹲伏、匍匐、贴墙、探头和换姿势停顿；警戒触发使用瞬时图形和声音钉。
- UI：视野扇形、雷达和通讯界面是独立条件模块，不默认同时出现。
- 条件剧情：渗透任务、身份冲突和军事议题，仅在剧本或完整游戏化中启用。
- 禁止漂移：不要把任意冷色古早 3D 画面自动军事化；通讯界面不得与普通实机镜头混成同一构图。

### 4.4 `platformer_mascot`

**核心关系**：轨道关卡与深度方向 → 高辨识角色轮廓 → 顶点式挤压拉伸 → 收集物和碰撞反馈。

- 默认视觉：高饱和大色块、纯净天空、少量 blob shadow、卡通低模角色。
- 相机：沿关卡轨道跟随，高度、俯仰和侧向角度受限；只在预设节点离散重新居中或切换方向。禁止自由环绕、超前飞行和离开关卡路径展示角色。
- 动作：预压缩、跳起拉伸、旋转攻击和表情部件联动；关键姿势优先于自然物理。
- 特效/UI：星星、感叹号、木屑、收集物高光按事件触发。
- 条件剧情：荒诞冒险、关卡推进和夸张反派，仅在完整游戏化中启用。
- 禁止漂移：身份锁定时保留角色标志轮廓；不要因“卡通”变成现代平滑赛璐璐动画。

### 4.5 `fighter_arena`

**核心关系**：侧向竞技舞台 → 招式轮廓清晰 → 固定前摇、命中停顿和硬直 → HUD 与胜负演出反馈。

- 默认视觉：相对更精细的角色模型、开放舞台、静态远景或天空盒。
- 相机：固定侧向舞台轴，不越过双方形成的 180 度轴线；只允许按角色距离有限水平平移或分档缩放。命中、终结或胜负时可短促切近，随后返回侧向机位；禁止环绕格斗者。
- 动作：少量关键姿势驱动的硬朗格斗动作、固定收招、短 hit stop、浮空与脚本化倒地；不使用现代动作捕捉式连续补间。
- 特效/UI：拳脚火花、生命条、计时和连击数字只在对战输出启用。
- 条件剧情：格斗大会、角色小传和独立结局，仅在完整游戏化中启用。
- 禁止漂移：不要加距离雾遮挡角色；不要用现代布料、头发物理和连续慢动作削弱招式节拍。

### 4.6 `action_adventure`

**核心关系**：网格化空间与可读平台边缘 → 第三人称跟随 → 完整不可中断的跳跃/抓边动作 → 机关和环境反馈。

- 默认视觉：全 3D 遗迹、洞窟、城市或其他探索空间，块状建筑几何和低分辨率材质。
- 相机：使用受限后方或斜后方跟随机位，距离、高度和俯仰基本固定；转向时分段重新居中，不连续环绕。抓边、机关或载具事件可切到预设脚本机位；禁止无人机式自由飞行和自动寻找最佳构图。
- 动作：网格式跳跃、抓边、引体、侧滚和后跃，起止状态明确。
- 特效/UI：水面贴片、火把光晕、灰尘和拾取物闪光按场景启用。
- 条件剧情：跨区域探险、文物、谜题和古代力量，仅在剧本或完整游戏化中启用。
- 禁止漂移：探险主角不必是特定性别或职业；不要把所有场景强制改成遗迹。

### 4.7 `monster_rpg`

**核心关系**：柔和自然空间 → 主角与怪物的伙伴关系 → 捕获/召唤的仪式动作 → 有机粒子和声音响应。

- 默认视觉：柔和动漫低模人设、森林或民俗幻想空间、有机拟兽拟虫怪物。
- 相机：探索采用固定高度的后方或斜俯视机位，伙伴与角色保持同屏可读；战斗使用双方对置的固定舞台轴。指令、召唤或命中只允许短促事件切镜，随后返回主机位；禁止持续围绕怪物旋转。
- 动作：主角动作柔和，召唤或融合具有明确手势；怪物保持个体化待机循环。
- 特效/UI：丝线、茧、萤火和融合光效仅在对应机制启用。
- 条件剧情：捕获、融合、村落、民俗和成长主题，仅在完整游戏化中启用。
- 禁止漂移：不要默认把所有角色改成特定现有作品人物；不用固定地域符号覆盖用户世界观。

## 5. 预设混合规则

- 先指定一个主预设，负责场景结构和相机。
- 次预设只能负责用户明确选择的动作、角色形体、特效、UI、剧情或声音维度。
- 不混合互斥相机：同一游戏状态不能同时采用固定恐怖机位、轨道平台相机和格斗侧视舞台。
- 不混合冲突的角色比例、相机和界面逻辑；同一画面保持一个清楚的主视觉系统。
- 不把内容母题当作混合条件；“恐怖剧情＋JRPG 战斗”应写成剧情和战斗维度分工，而不是整体叠加两个 preset。

## 6. 连续性系统

多图或多镜头锁定：

- 角色身份、比例、面部贴图、发型、服装和关键轮廓
- 武器、道具、持握手、损坏状态和位置
- 场景平面关系、入口出口、遮挡和导航路径
- 材质分辨率感、光影烘焙方式和表面颗粒
- 主光方向、综合色倾向和雾强度
- 相机状态、游戏状态和空间方向
- 动作起始姿态、结果、硬直、倒地和复位状态
- 一个镜头只执行一个主要动作，并只产生一个持久交互状态变化；含“并、然后、再、同时”的复合动作默认拆镜。只有动作步骤不可分割且最终仅改变一个持久状态时，才可视为一个原子动作。后一镜继承前一镜的持握手、道具位置、角色朝向、机关状态和动作结果
- `retro_gameplay_display` 的像素簇、扫描线、色彩溢出和辉光强度跨镜头稳定

多镜头中保持角色精度、身份与道具稳定；只有用户明确要求视觉升级或预渲染视频质感时才改变表现精度。

## 7. 负面约束

按任务选择相关项，不机械堆叠：

- 装饰性三角/四边切面、多边形马赛克、wireframe、晶体切割和 faceted low-poly 插画
- 独立湿润眼球、建模眼睑鼻孔唇峰牙齿、皮肤毛孔、细发丝和现代发片
- 现代 PBR、次表面皮肤、光线追踪、细密高模与微观材质参数
- 连续柔顺补间、过度平滑 IK、动作捕捉式细小重心修正、布料和头发物理
- 仅加扫描线而形体与材质仍现代，或用强噪点、glitch 和几何碎片冒充早期低规格实时 3D 的显示缺陷
- 身体、脸、服装、道具和背景物体随机融化、透明重组、换形、换手或凭空出现
- 未授权的 UI、文字、武器、敌人、血迹、角色或剧情变化
- 同一镜头混用互斥预设、角色比例或相机逻辑；把视觉低清晰度误当作必须降低最终文件尺寸

## 8. 内置参考素材职责

完整素材清单、路径、适用条件、非证据边界和组合规则见 [reference-manifest.md](reference-manifest.md)。选择素材时必须使用该 manifest，不凭文件名猜测职责，也不默认加载全部素材。

四张核心素材分别负责角色形态、实时渲染、界面组件和动作/特效生命周期；七张预设素材分别负责对应题材中“场景结构—相机—动作—反馈”的关系。核心素材回答“如何表现”，预设素材回答“关系如何组织”，用户素材回答“具体是谁、是什么以及必须保留什么”。

角色参考板是形态空间，不是角色目录。先选 R、J 或 M 行，再只选一个编号锚点；把 [reference-manifest.md](reference-manifest.md) 中该编号的比例、躯干、肢体、手脚、轮廓和面部表达完整展开进提示词，不在运行时重新测量，也不混合其他编号。编号不代表固定身份；用户的身份、发型、服装、配色和道具仍需重新设计，不得复制参考板中的完整角色。
