## 1. 组装顺序

提示词按以下顺序组织，只填当前任务需要的字段：

```text
{主体、身份与关系}
+ {场景和叙事动作}
+ {style_mode}
+ {主预设和启用维度}
+ {构图与相机}
+ {形体、贴图、材质与光影}
+ {动作、特效、UI 或声音}
+ {保留项和禁止新增项}
+ {连续性锚点}
+ {用户或上游明确的输出规格}
```

不要把视觉参考参数写成最终输出规格。用户需要高清、大画幅或非典型画幅时，保留交付规格，同时在画面内部模拟古早低规格实时 3D 的几何、贴图和显示质感。

## 2. 任务路由摘要

生成正式提示词前先按 [reference-manifest.md](reference-manifest.md) 形成内部配置。故事、剧本或纯文字方案默认不选图；其他任务只选最少够用的内置素材，默认 2–3 张、上限 3 张。

```yaml
early_3d_configuration:
  input_mode: {任务类型}
  style_mode: {faithful_transfer | style_enhanced | full_gameification}
  primary_preset: {七预设之一 | core_only}
  enabled_modules: [{只列当前任务开启的 character_shape, rendering, scene, camera, motion, effects, interface, narrative, sound, display}]
  character_anchor_id: {R/J/M 行中的唯一编号；无角色时省略}
  display_mode: {视频默认 retro_gameplay_display | 用户明确要求无显示处理时 clean_render | 非视频 not_applicable}
  ui_decision:
    state: {include | omit | not_applicable}
    reason: {对场景图必须填写；非场景任务写 not_applicable}
  must_preserve: [{锁定内容}]
  may_transform: [{允许改变内容}]
  must_not_add: [{禁止新增内容}]
  inherited_output_spec: {只写用户或上游明确值}
reference_plan:
  - asset: {asset_id 或用户参考图}
    role: {本任务中的唯一主要职责}
    exact_cues: [{实际抽取的 2–4 个可观察点}]
    do_not_copy: [{不得继承的身份、服装、地点、构图、UI 或偶发细节}]
```

任务包含角色时，再形成固定块；同一角色后续原样复用，只改变获准字段：

```yaml
character_render_lock:
  character_anchor_id: {唯一编号}
  proportion_and_silhouette: {从 manifest 展开的比例、躯干、肢体、手脚与轮廓}
  identity_face: {用户要求的眼窝感、眉形、唇形、年龄感和情绪}
  face_rendering: {上述特征如何压缩为低分辨率贴图、少量大色块和极少几何}
  topology_and_shading: {轮廓与关节有限分段；大平面连续平滑着色}
  material_groups: [{压缩后的 3–4 个材质视觉组}]
  forbidden_style: [装饰性三角切面, 多边形马赛克, 现代PBR脸, 细发丝, glitch碎片]
```

## 3. 文生图模板

```text
主体与关系：{人物、物体、人数、身份、关系和关键道具}。
场景与动作：{地点、时间、正在发生的动作和叙事重点}。
风格模式：{style_mode}。
题材配置：以 {primary_preset} 为主，启用 {enabled_modules}；{如有次预设，说明它只负责的维度}。
构图与相机：{景别、机位、空间关系；服从预设的场景—相机逻辑}。
形体与表面：使用“低模本体 + 平滑表面”；肩、肘、膝、靴子、头部和道具外轮廓有限分段，躯干与四肢大平面连续平滑着色，拓扑只在轮廓和关节处可见。禁止装饰性三角/四边切面、随机多边形马赛克、wireframe、晶体切割和 faceted low-poly 插画。
角色锚点：{展开唯一编号的比例、躯干、肢体、手脚和轮廓；无角色则省略}。成年仅表示年龄与身份，不改变锚点比例。
面部：身份特征为 {眼窝感、眉形、唇形、情绪}；这些特征仅通过低分辨率脸部贴图、少量大色块和极少几何隆起表达，不增加现代五官结构。
贴图与材质：{压缩后的 3–4 个视觉组；每组只写综合色块、有限明暗和最多一个辨识特征}，使用烘焙明暗，不使用现代 PBR 微观细节。
光影与色阶：{题材对应的综合色关系、顶点着色感、有限明暗层级、抖色或距离雾强度}。
UI 判断：{引用 ui_decision.state}，理由：{引用 ui_decision.reason}。
特效与 UI：{只写已启用内容；若 include，只加入必要组件并说明位置与信息层级；粒子优先使用有限帧 billboard sprite}。
必须保持：{用户要求锁定的内容}。
禁止新增：{未授权的角色、敌人、UI、文字、武器、剧情或环境元素}。
输出规格：{仅继承用户或上游明确值}。
```

### `core_only` 简版

用于用户只说“古早 3D 游戏风格”且无法可靠判断题材时：

```text
保留用户主题和内容，不自动加入特定游戏题材。使用不可拆分的“低模本体 + 平滑表面”：有限分段只在轮廓和关节处可见，大平面连续平滑；配合低分辨率数字贴图、有限明暗和简单 sprite 特效。视频默认启用 `retro_gameplay_display`；静态图不默认加 CRT。HUD 服从 `ui_decision`。
```

## 5. 文生视频模板

所有视频默认写入下方显示链；只有 `display_mode: clean_render` 时删除该段。每个镜头只执行一个主要动作，并只产生一个持久状态变化。含“并、然后、再、同时”的复合动作默认拆镜；只有不可分割且最终仅改变一个持久状态的原子动作才可保留在同一镜头：

```text
镜头编号：{编号}
游戏状态：{探索 | 战斗 | 剧情 | UI}
主预设：{primary_preset}
起始状态：{人物姿态、位置、朝向、持握手、道具位置、环境、光线和 UI}。

主体动作：先保持 {准备姿势}，随后快速完成 {一个主要动作}，在 {结果姿势} 上短暂停住，再以少量过渡进入 {复位或下一状态}。关键姿势连续保持若干画面后明显切换，不使用连续柔顺的加速减速或动作捕捉式补间；减少脚踝、髋部、肩部和手腕的细小自动校正，允许轻微脚滑与硬关节。
环境响应：{有限帧 sprite、道具、灯光或背景反馈；只写本镜需要的内容}。
相机：{直接使用下方主预设相机句式，并写明机位、允许移动和唯一切换条件}。
形体保持：轮廓和关节有限分段，大平面连续平滑；模型、脸、服装和道具拓扑稳定，不产生三角碎片、融化或随机换形。
显示层：整个视频始终像低分辨率游戏缓冲画面被放大到最终尺寸；像素簇跨镜头稳定，硬边放大，有限色阶与有序抖色，轻微扫描线，克制的横向色彩溢出和少量高亮辉光；不得恢复现代高清脸部或材质细节。
结束状态：{供下一镜继承的人物姿态、朝向、持握手、道具位置、机关状态、光线和 UI}。
输出规格：{仅继承用户或上游明确值；不得靠降低文件分辨率实现显示层}。
```

## 6. 图生视频模板

```text
参考职责：{逐张写作用与 2–4 个具体视觉点；角色只用一个编号锚点}。
必须保留：{身份、比例、服装、道具、起始构图和场景锚点}。
允许运动：{每镜一个主要动作、预设允许的相机行为、必要环境反馈}。
禁止改变：{未授权的脸、服装、背景、道具、角色和剧情}。

起始状态严格继承参考图。主体先保持准备姿势，快速完成一个主要动作，在结果姿势上短暂停住，再用少量过渡复位或衔接；关键姿势分段保持，不连续平滑补间。相机严格使用 {primary_preset} 的相机句式。一个镜头只执行一个主要动作并只产生一个持久状态变化；含“并、然后、再、同时”的复合动作默认拆镜，只有不可分割且最终仅改变一个持久状态的原子动作才可保留。没有经过可见动作，道具不得出现、消失、换手或改变状态。全过程保持角色锚点、低模轮廓、平滑大表面、贴图、空间方向和道具身份稳定。
显示层：默认使用 `retro_gameplay_display`，将低分辨率游戏画面以稳定像素簇、硬边放大、有限色阶、有序抖色、轻微扫描线和克制色彩溢出呈现在用户指定的最终分辨率中。
输出规格：{仅继承用户或上游明确值}。
```

### 七预设视频相机句式

将对应句式直接写进视频提示词，不只写“符合预设”：

- `survival_horror`：相机固定在区域预设位置，角色移动时相机不跟随；只有跨过门口或区域边界才硬切到下一固定机位。禁止环绕、推进跟拍、手持和自动找角度。
- `jrpg_epic`：探索使用固定或缓慢脚本机位；战斗锁定三分之四侧向舞台。技能只允许一次短促切近或单轴推进，随后返回主机位。
- `stealth_action`：使用受限俯视或斜俯视战术机位，只在固定边界内缓慢跟随；保持地图方向，不穿墙、不绕到正面，事件结束后返回战术轴线。
- `platformer_mascot`：相机沿关卡轨道移动，高度、俯仰和侧向角度固定在有限范围，只在预设节点重新居中或切换方向。
- `fighter_arena`：相机固定在侧向舞台轴，不越过 180 度轴线，只按角色距离有限平移或分档缩放；事件切近后立即返回。
- `action_adventure`：保持受限后方或斜后方机位，距离、高度和俯仰基本固定；转向时分段重新居中，只有机关或载具事件进入预设脚本机位。
- `monster_rpg`：探索使用固定高度后方或斜俯视机位；战斗锁定双方对置舞台轴。指令或召唤可短促切镜，随后返回主机位。

## 7. 分镜模板

先写全局配置，再逐镜头写差异：

```yaml
sequence_bible:
  style_mode: {模式}
  primary_preset: {主预设}
  enabled_modules: [{启用模块}]
  character_render_lock: {唯一编号锚点及固定比例、面部、着色和材质组}
  scene_anchor: {空间布局、入口出口、遮挡和导航路径}
  camera_rule: {对应预设相机句式、机位编号和切换条件}

  must_not_add: [{禁止新增项}]
```

逐镜头：

```text
镜头 {编号}｜{游戏状态}
画面目的：{这一镜承担的信息或情绪}

构图与机位：{符合预设内部逻辑}
动作与反馈：{关键姿势、环境响应、特效或 UI}
结束状态：{供下一镜继承}
允许变化：{本镜独有变化}
禁止漂移：{身份、角色精度、空间、光线和道具}
```

## 8. 故事/剧本创建与改写模板

只在用户要求故事、剧本或完整游戏化时启用剧情模块。没有原稿时使用 `create`，已有原稿时使用 `adapt`。

```yaml
narrative_configuration:
  mode: {create | adapt}
  premise: {一句话前提}
  protagonist_goal: {主角的可执行目标}
  central_obstacle: {核心阻碍或对抗关系}
  must_preserve: [{已有角色身份、关系、事件、结局、台词或世界观硬约束}]
  primary_preset: {primary_preset | core_only}
  enabled_modules: [{只选剧情需要的探索、战斗、追击、对话、谜题、比赛、捕获等}]
  forbidden_motifs: [{用户排除或预设中不得自动加入的母题}]
```

创建规则：
1. 由前提建立开端、升级、转折、高潮选择和结局状态；缺失信息只作最少必要假设。
2. 每个场景写清目标、冲突、玩家可见信息、状态变化与离场条件，不要求探索、战斗、剧情和 UI 全部出现。
3. 对白保持短句和消息框节奏；重要台词可独占一屏。
4. 舞台说明明确机位、动作、必要的 UI 和声音钉。
5. 使用预设的场景—相机—动作—反馈关系，不照搬参考游戏的角色或情节。
6. 只继承用户明确的篇幅、章节数和格式；未指定时输出一个简洁、完整、可扩写的基础版本。

改写规则：
1. 先列出必须保留的剧情事实，再调整场景顺序、互动节点、对白长度和演出方式。
2. 不擅自改变人物关系、结局或世界观硬约束。
3. 预设只提供组织逻辑，不用其典型母题覆盖原稿。

输出片段格式：

```text
【场景 {编号}｜{探索/战斗/剧情/UI 或自定义状态}】
场景目标：{玩家或角色在本场要完成什么}
冲突与可见信息：{阻碍、线索和玩家能观察到的内容}
机位与环境：{说明}
角色与动作：{说明}
角色名：{短对白}
反馈：{必要的特效、UI、环境或声音；无则省略}
状态变化：{本场发生了什么改变}
离场条件：{下一段继承内容}
```

## 10. 连续性块

```yaml
continuity_lock:
  character_render_lock: {复用同名固定块；包含唯一编号、身份、脸、比例、发型、服装与轮廓}
  scene_anchor: {平面关系、入口出口、遮挡与导航路径}
  material_anchor: {贴图分辨率感、烘焙光影与表面颗粒}
  light_anchor: {主光方向、综合色倾向、雾与时间状态}
  camera_anchor: {游戏状态、机位和切镜条件}
  motion_anchor: {动作起点、结果、硬直、倒地或复位状态}
  prop_anchor: {关键道具、持握手、位置与损坏状态}
  interaction_state: {本镜开始状态 -> 本镜唯一主要变化 -> 本镜结束状态；无复杂交互时省略}
  interface_anchor: {HUD、菜单、警戒与战斗状态}
  display_anchor: {retro_gameplay_display 的像素簇、扫描线和色彩溢出强度跨镜头稳定}
  character_fidelity_anchor: {角色精度与跨镜头稳定性}
  allowed_variation: {允许随镜头变化的项目}
  forbidden_drift: {禁止漂移项目}
```

## 11. 负面约束模板

只选择与当前任务相关的项：

```text
避免装饰性三角/四边切面、多边形马赛克、wireframe、晶体切割和 faceted low-poly 插画；避免独立湿润眼球、建模眼睑鼻孔唇峰牙齿、次表面皮肤、毛孔、细发丝、现代发片和 PBR 角色展示；避免把材质展开为织物纤维、连续磨损、粗糙度或金属度。视频避免连续柔顺补间、动作捕捉式重心修正、自由环绕、无人机、手持、自动构图跟随和未获预设允许的运镜；避免只加扫描线而形体材质仍现代。模型拓扑、比例、脸、服装和道具身份必须稳定，只允许轻微视角相关的轮廓跳动与贴图游动，禁止融化、透明重组、新增几何碎片、换手、凭空出现或状态跳变。
```
